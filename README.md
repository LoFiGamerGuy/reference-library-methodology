# Reference Library Methodology

A system for building a queryable, AI-readable technical reference library from your own books, papers, and notes. Optimized for use alongside agentic AI tools (Claude Code, Cursor, Aider, etc.) where the library serves as long-term semantic memory across sessions and projects.

This repo is the **methodology and tooling**, not the corpus itself. You bring your own books and notes; the system gives you the structure, the extraction tools, the cross-book synthesis pattern, and the MCP server that exposes the result as an agent-queryable reference.

## What this solves

Most personal-knowledge-management approaches are wrong-shaped for AI:

- **Notion / Roam / Obsidian alone** — great for human browsing, but agents can't easily query them at session start
- **RAG over a vector store** — opaque retrieval, hard to audit, slow to update, expensive at scale
- **Reading without extraction** — you read 100 books; you remember 5 patterns; the other 95 books' value evaporates

This methodology produces:

- **One-time INSIGHTS extraction per book** — agent-readable, focused on non-obvious patterns. Done once; consumed many times.
- **Cross-book synthesis docs** — patterns that emerge across multiple books, distilled into focused references.
- **Per-project reading lists** — tier-ranked book maps that route an agent (or you) to the right material at session start.
- **A session quick-start tool** — one command produces a context block to paste into a session, listing relevant books + their INSIGHTS + relevant synthesis.
- **An MCP server** — exposes the library as TF-IDF search over INSIGHTS, plus per-project context queries. No vector DB, no API key, fully local.

The result: a library that takes weeks to build, then pays back for years. Books you've extracted INSIGHTS for are usable as agent context in seconds, not "I should re-read that someday."

## Quick start

### 1. Clone and install

```bash
git clone https://github.com/LoFiGamerGuy/reference-library-methodology.git
cd reference-library-methodology

# Install Python dependencies
pip install anthropic python-dotenv mcp

# (Optional) Add your Anthropic API key for INSIGHTS extraction
cp .env.example .env
# Edit .env and set ANTHROPIC_API_KEY=sk-ant-...
```

### 2. Set up your library directory

The repo expects you to keep your library content **outside** this repo (because of copyright — your books are yours, not for redistribution). The recommended structure:

```
~/my-reference-library/        # your library — separate from this repo
├── INVENTORY.md                ← auto-generated by tools/regenerate_inventory.py
├── _maps/                      ← project-specific reading lists
│   ├── INDEX.md
│   ├── project-a.md
│   └── project-b.md
├── _synthesis/                 ← cross-book pattern docs
│   └── topic-x-patterns.md
├── ai-agents/                  ← books grouped by category
│   ├── book-slug-1/
│   │   ├── content.md          ← extracted text (you provide; copyright-aware)
│   │   ├── INSIGHTS.md         ← agent-extracted patterns (this repo's tools generate)
│   │   └── images/
│   └── book-slug-2/
└── shells-scripting/
    └── book-slug-3/
```

See [docs/library-structure.md](./docs/library-structure.md) for the full layout and naming conventions.

### 3. Add your first book

For a book you have legitimate access to (purchased, public domain, or fair-use excerpts):

```bash
# Convert EPUB to markdown
python tools/epub_to_md.py path/to/book.epub --library ~/my-reference-library

# Extract INSIGHTS (requires ANTHROPIC_API_KEY)
python tools/batch_extract_insights.py --library ~/my-reference-library --slug book-slug-1
```

See [docs/insights-extraction.md](./docs/insights-extraction.md) for what INSIGHTS extraction does, what it costs, and how to tune the prompts.

### 4. Build a project map

A project map is a tier-ranked reading list — "for this project, these books matter most." Copy [`templates/project-map.template.md`](./templates/project-map.template.md) to `_maps/<project-slug>.md` and fill in the books that bear on the project.

```bash
python tools/load_context.py --library ~/my-reference-library --project project-a --clip
```

The output is a context block ready to paste at session start. Listed books, available INSIGHTS paths, relevant synthesis docs.

### 5. (Optional) Register the MCP server

For Claude Code to query the library directly:

```bash
claude mcp add reference-library -- python /absolute/path/to/tools/mcp_server.py /absolute/path/to/your/library
```

See [docs/mcp-server.md](./docs/mcp-server.md) for the full MCP integration.

## Costs

The methodology has a real cost — both money (LLM API for extraction) and time (the discipline of building it):

- **Per-book INSIGHTS extraction:** ~$0.03–$0.30 depending on book length and model (haiku vs sonnet). For a 150-book library, batch extraction runs ~$5–$45 total.
- **Time to extract a single book:** ~30 seconds with the batch tool. Manual review and refinement: ~5–15 minutes per book if you're being thorough.
- **Time to build the system from scratch:** ~1 day for a 50-book library if you're focused. Less for smaller; more for ongoing additions.

The payoff: every subsequent agentic session that uses the library is faster, more accurate, and produces less hallucination. The library compounds in value as you add to it.

## Copyright awareness

This methodology is for **your own** books and notes. The repo's hard rules:

- Public-domain text may be stored in full
- In-copyright works: bibliographic metadata + structured summaries + fair-use excerpts only
- No gray-channel acquisition

The Tier A/B/C framework (see [docs/copyright-tiers.md](./docs/copyright-tiers.md)) lets you operate at the copyright tier you're comfortable with. Tier A (citations + summaries, no source text) is the floor; everything in your library has at least Tier A.

This repo ships **only the methodology and tools**. No book content. The corpus is yours to assemble per your own copyright posture.
